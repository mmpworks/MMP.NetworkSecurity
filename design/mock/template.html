A longer text, many blocks

AES only locks 16 bytes at a time. A mode decides how many blocks work together. ECB locks each block alone. CBC first mixes each block with the cipher block before it.

This tab uses AES-128 in the mock, whichever key size is picked above.

The same idea with a picture

Flat areas make many equal blocks. ECB turns equal blocks into equal cipher blocks, so the shape stays. CBC gives each block a different start, so the shape goes.

Each pixel is one byte, so each block is 16 pixels of one row. Same test key in both. AES works the same way inside both: only the mode differs. A mode like CBC still needs a tag to stop changes, which GCM adds.

GCM: AES as a stream

In GCM, AES never locks your text. It locks a counter, and the answer is a key stream. Your text then XORs with that key stream one byte at a time. So the text can be any length, with no padding, and a byte can go out as soon as it is ready.

The tag: why a stream needs one

A stream alone stops reading, and it does not stop changes: a flipped bit on the wire flips the same bit in the text. So GCM adds a tag. AES of 128 zero bits gives a secret value, H. Each block is XORed in and multiplied by H, in a 128-bit Galois field. AES of the first counter then masks the result.

HMAC: proof, not a lock

AES hides bytes. HMAC hides nothing: it proves that a message was not changed, and that it came from someone holding the key. It is built from a plain hash and a key (, ).

The chain: each tag covers the last one

The Chain of Custody spec tags every event this way: tag = HMAC-SHA-256(session key, previous tag + event). The spec calls this tag payload_hash. The first event uses 32 zero bytes as its previous tag. These 5 events and tags are the spec's own public test values, case 002. The spec is a Public Review Draft.

The daily seal

Once a day, the tags go into a , and its root gets signed in a hardware key store. The mock does not run that signature. A new root needs a new signature from that store. The signing key cannot leave it, and only the seal job may ask it to sign. This protects a day already sealed. Before the seal runs, the chain records whatever the key holder writes. The reader must also get the signer's public key from somewhere other than the file's holder: a rewriter who signs with their own key passes against their own public key.

A Feistel network: another way to build a cipher

A Feistel network is a structure, and you choose what goes inside it. It splits the block in half and changes one half per round. To decrypt, you run the same steps with the keys in reverse order. So F never has to run backward, and F can even be a one-way hash. DES is built this way ().

Diffie-Hellman: agree on a secret in public

AES needs both sides to hold one key. So how do two strangers get that key when anyone can read the wire? They never send it. Each side keeps a private number and sends a public one. Then both work out the same secret. Published in 1976, this idea still starts most of your browser's secure connections, in a newer form.

These numbers are small so you can follow them, and they are not safe. The real thing is further down.

The same idea in paint

Mixing paint is easy, and unmixing it is hard. Each side adds its own private color to the shared one and sends the mix. Then each adds its private color to the other's mix. Both end with the same three colors in the pot. This is a picture of the idea, not the math.

The real thing: X25519

This uses the same steps, with a curve in place of the powers, and with 32-byte numbers. These are the published test values from , section 6.1. A script ran both sides and got this secret. The last row feeds the secret through to make a key for AES, with a label made up for this page. TLS 1.3 does the same step with its own labels, with more steps, and with a hash of the handshake.

A full TLS 1.3 handshake makes new private numbers, then deletes them. So if a server's long-term key leaks later, old recorded traffic stays locked, unless someone later breaks the exchange itself. That risk is why lesson 3 adds ML-KEM. This is called forward secrecy.

The math under MixColumns

  1. A field is a set of values with add, subtract, multiply and divide, where every answer stays in the set. Only divide by zero is not allowed. They follow the usual rules of arithmetic.
  2. A finite field has a fixed number of values. Another name for it is a Galois field. The field that AES uses has 256 values, one for each byte. Its name is GF(2^8).
  3. Add is XOR.
  4. Multiply treats each byte as a polynomial, multiplies without carries, and reduces the result by x^8 + x^4 + x^3 + x + 1 (11b in hex). So the answer always fits in a byte.
  5. Every value except zero has an inverse. So multiplying by any nonzero value can be undone.
