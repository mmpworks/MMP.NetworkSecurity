# Learnings

Each correction goes here, newest slice last. Later slices read this file first.

## S0

1. **A CF exe needs `GenerateSupportedRuntime=false` and an `App.config` that names v4.0.** The SDK default writes `supportedRuntime v2.0.50727`. On this machine that exe printed nothing and exited 0, which reads as success. The Host and the tests require the `CE-READY` line for this reason.
2. **Only socket events carry `Wire`.** A10a joins every `wire` field of the client actor by direction and compares to the tap. So the engine event (`echo.message.sent`) carries `Plain` and `Fields`, and the pump's `wire.sent` and `wire.received` carry `Wire`, `From`, and `To`. The program design first said an engine event carries `Wire`. That shape would double the bytes. The design's "skips the gate" line for `wire.sent` is also dropped, because the tour binds to `wire.sent` and must pause on it.
3. **Socket events have their own stream, `<streamId>/wire`.** TCP chunking changes between runs, and `wire.received` follows it. The engine stream stays fixed across same-seed reruns, and a tamper plan addresses that stream. Compare runs on the engine streams only.
4. **`state.waiting` fires on a state change, never per `Feed`.** One event per `Feed` would make the engine's sequence numbers follow TCP chunking.
5. **`EngineOutput` holds `Items`, one event with its optional wire bytes.** The design had separate `Wire` and `Events`. The gate must hold each message and its bytes together, so the pump writes the bytes right after the event passes. `Wire` and `Events` stay as read-only views.
6. **Machine cannot name `AppChunk`, because the contract keeps it in Io.** `EngineOutput.App` holds `Machine.DeliveredChunk`, and the pump turns it into `AppChunk`.
7. **`tools/layer_check.py` carries two named exceptions from the contract:** `Io` names `NetSec.Bridge.DeviceProfile` by full name, and `Machine/IStepGate.cs` uses MMP.AsyncProxy.
8. **A test project reference to a CF project needs `SetTargetFramework="TargetFramework=net35"`.** `SkipGetTargetFrameworkProperties` leaves the test's own TFM on the build, and restore fails with NETSDK1005.
9. **`--socket-loop` closed the S0 spike.** `CE-RESULT` shows all four Begin pairs ran on the CF binaries on net48. The Compact Framework runtime itself has run nothing.
10. **`NetSec.Node` is not in S0.** `acceptance/run.ps1` reports the bridge group NOT RUN PRODUCT_MISSING until S5.
11. **A flipped length byte leaves a receiver waiting forever, so every real engine lesson (S3 on) needs a read timeout that ends in a named error.** The length promises bytes that never come, and no check runs. In free run the pump's deadline ends the wait with `LINK_DEADLINE` (`EchoLab` uses 30 s, and a test pins the code). In step mode the pump has no deadline, because a learner can read for an hour, so that wait still has no end. S3 must decide who ends it. A deadline in the engine's waiting state, counted only while the gate is open, is the first candidate.
12. **The toy is lesson 0 and sits outside `GET /api/lessons`, which holds lessons 1 to 11 (lead's ruling).** `session.start` accepts 0. `GET /api/lessons/0` gives its row.

## S1

1. **The `prim` group compiles as one program, so A1 and A2 stay NOT RUN until every Crypto type exists.** `Subject.Product.cs` names all of section 2.3. A partial Crypto folder fails the compile, and all 64 clauses report PRODUCT_MISSING, including the primitives that work. To read a partial result, add the rest of `acceptance/contract/Crypto.cs` as an uncommitted file (its bodies throw `NotImplementedException`, which maps to NOT RUN), run the clauses, and delete the file. The full gate reports the acceptance step as FAIL until both S1 lanes merge.
2. **The `FromBytes`, `Ek`, and `Dk` names hold, not `FromBigEndian` or `EncapsulationKey`.** The acceptance suite changed these names in `fdfcf81`. Read the merged `acceptance/contract/Crypto.cs` before you code to an older `CONTRACT.md` line.
3. **`X25519.Mult` does not refuse an all-zero result.** RFC 7748 leaves that check to the protocol. S3 must add it to the TLS 1.3 key share and S4 to the SSH exchange.
4. **`Ed25519.Verify` accepts a small-order public key.** A public key at y = 1 with R = B and S = 1 verifies for any message. RFC 8032 allows this. A protocol that needs a stronger rule adds its own check. `Verify` refuses a wrong length, S at or above L, a public key with y at or above p, a y with no square root, x = 0 with the sign bit set (RFC 8032 section 5.1.3 step 4), and an R that differs in bytes from the computed value. Go accepts the x = 0 case with the sign bit set, so a Go referee cannot catch it. A builder test pins it.
5. **`RsaPrivate` holds n and d only, so it runs the full-size exponent.** Parsing a PKCS#8 key can drop the CRT values. On a real device this makes a private operation slower than a CRT one by a factor of about 4 (standard estimate, not measured here).
6. **A2 tests valid ML-KEM exchanges only.** Implicit rejection and the key checks are reached by 36 NIST ACVP records in `tests/NetSec.Tests/vectors/mlkem768-acvp.txt`.
7. **For S4: `DhGroup14` returns 256 fixed bytes, and SSH hashes e, f, and K as mpints.** Strip the leading zeros, and add one 00 byte when the top bit is set. A value with a leading zero byte comes about 1 session in 256, so a run with no conversion can pass by luck. Test both forms: a value with a leading zero, and a value with the top bit set.
8. **For S4: an even RSA modulus reaches `BigUInt.ModPow` as an unnamed `ArgumentException`.** SSH host keys come from the wire, so S4 needs a named error before that call.
9. **For S4: `Pkcs1.VerifySha1` and `VerifySha256` throw `RSA_MESSAGE_TOO_LONG` on a modulus too short for the digest.** Other bad input returns false. S4 must catch this code when the key comes from the wire.

## Lessons 1 to 3

1. **Each side of a lab needs its own random stream.** Two pumps draw in an order the threads choose, so one shared stream gives different bytes on a same-seed rerun. `LabPair.Fork` draws a seed per side before the pumps start. Fork matching (`atSeq`) depends on this.
2. **A rule reads a value only through `FrameSession.Secret`, and `Effect.Secret` stores it.** The interpreter calls `Remember`, so a rule stays free of side effects except `Draw`, which reads the side's random stream in rule order.

## S2

1. **`openssl genpkey -outform DER` on OpenSSL 3.5.7 wrote a traditional `RSAPrivateKey`, not PKCS#8.** CONTRACT rule 5 needs `PrivateKeyInfo`. Run `openssl pkcs8 -topk8 -nocrypt` after it. `An_rsa_key_is_pkcs8_with_its_matching_spki` pins the format on both builds.
2. **`TrainingKeySource.Find` throws `TRAINING_KEY_UNKNOWN` for an unknown id.** It never returns null. A symmetric key's `CopyPublic` gives an empty array.
3. **`DukptPinPad.Next` uses a new counter on each call (CONTRACT.md).** The S5 `PinEnvelope` holds one KSN, a PIN block, and a MAC. So S5 needs both keys under one counter and must add a method to the pad that returns several working keys for one counter. The derivation already allows it: `DukptDerivation.Working` takes the usage per call.
4. **Lesson 6 has no MAC on the wire, by the UX row.** A flipped PIN block must reach `PIN block format check`, and a MAC would catch it first. `DUKPT_MAC_MISMATCH` stays for S5.
5. **`held` does not fall on every sale.** A sale erases one register and can fill lower ones with child keys: 32 after the load, then 31, 31, 30, 31. UX moment 5 says "the reader column shrinks". The lab reports the true count, and the tour must not promise a steady fall.
6. **The one-bit limit of 16 is from recollection of X9.24-3, which is paid.** The free vectors do not state it. Both sides agree past it in `DukptTests`, because the bank walks any counter.
7. **`DUKPT_COUNTER_EXHAUSTED` needs a pad that starts late.** Sales alone need about 2^31 calls to reach it. An internal constructor starts a pad at counter `0xFFFF0000`, and `NetSec.Tests` sees it through `InternalsVisibleTo`.
8. **`PumpTests.A_flipped_length_byte_...` raced.** Two 300 ms deadlines, so the client could close first, and the server then reported `PEER_CLOSED_EARLY`. It failed 1 of 2 gate runs. The server's deadline now comes first. A test with two deadlines must say which one ends first.
9. **The lab's reader session holds no base key.** Only `BankSession` holds it, and a test scans the reader's trace for it. S5 keeps this shape across processes (D13).
10. **A test under `#if NET` in `tests/NetSec.Tests` turns A9 red.** `A9.cf.same-suite-passes-on-net48-skips-pinned` compares the net10.0 and net48 test sets. PR #13 did this and blocked every lane. A BCL-only check goes in `tests/NetSec.Host.Tests`, which runs on net10.0 only. Run `pwsh acceptance/run.ps1 -Clauses A9` on every PR that adds a test.
11. **Record a KSN only after the sale passes every check (Jared's review of PR #22).** A ledger that records first lets a forged block under the next KSN burn it, and the real sale then gets `DUKPT_KSN_REPLAY`. `DukptBank.OpenPinSale` holds this order for lesson 6, and `BankHsmCore.Decide` holds it for S5, after its MAC check. The S5 bank had the same defect for a block with a valid MAC and a bad shape. `KsnLedger` now has `Contains` and `Record`, with no combined call, so a caller must choose the point of the record.
12. **A trace event states what the code did.** The lab reported `dukpt.initial` as erased and only dropped a reference. `Lesson06Dukpt.LoadReader` now clears the array before the event, and the trace holds its own declared copy. The managed-heap caveat never excuses skipping the clear.
13. **Do not clone keys to count them.** `HeldKeys` makes uncleared copies, so the lab reads `HeldCount`. Use `HeldKeys` only where a caller needs the bytes.
14. **Open question: strength of a derived key.** `DukptDerivation.Working` lets an AES-128 derivation key make an AES-256 working key. A reviewer recalls a rule against a derived key stronger than its parent. X9.24-3 is paid, so this is unverified, and the code does not refuse it.

## S3

1. **Decision: the read deadline counts only while the gate holds no event.** This closes S0 item 11. `EnginePump` restarts its clock while `StepGate.IsHolding` is true, so a learner can read one event for an hour. A read that stays open with nothing at the gate has no one left to wake it, and `LINK_DEADLINE` ends it, in free run and in step mode. `LabPair` now passes 30 s on both gates. A gate with no `IGateState` keeps the plain deadline. S5: `RemoteStepGate` must implement `IGateState`, or a node process in step mode gets a deadline that ignores the learner.
2. **`X25519.Mult` all-zero results are refused in `KeyExchange`, on both roles.** The code is `TLS13_X25519_ZERO`. S4 still owes the same check in the SSH exchange.
3. **A rule keeps a value with `Effect.Store(Action)`.** The rule returns the closure and the interpreter runs it, so the rule stays free of side effects. `Effect.Secret` plus `Remember` from lessons 1 to 3 holds byte arrays only. TLS keeps a suite and a parsed certificate too. It emits no trace event.
4. **A protocol with more than one kind of message uses `Effect.SendAs` and the 6-argument `InboundMessage`.** The trace type then names the kind: `tls.handshake.sent`, `tls.record.sent`, `tls.alert.sent`.
5. **A key share or ML-KEM ciphertext tamper is caught by the AEAD tag, not by Finished.** `ux-design.md` section 8 names `transcript hash` and `Finished verify_data`. The two sides hold different keys, so the first sealed record fails first. `docs/lessons-4-5-names.md` holds the corrected rows. A Finished flip must happen at the Plain tamper point, because a Wire flip fails the tag first.
6. **`ProbeRequest.Tamper` keeps its contract type `NetSec.Labs.TamperPlan`, which sits above `Io`.** `tools/layer_check.py` now names it as the second full-name exception, and it fails on any other `NetSec.Labs` name in `Io`.
7. **Lesson 4 and 5 attack rows use fixed byte offsets.** `Tls13Lab` lists the layout beside each constant. A change to the ClientHello extension order or the server name moves them, and `Every_attack_in_the_catalog_is_caught_by_its_named_check_beside_the_control` fails.
8. **The record-length attack must flip the last record of a flight.** A larger length on an earlier record is filled by the records after it, and the receiver then fails the tag and never waits.
9. **`Probe` throws `NotImplementedException` for TLS 1.1 and SSH until S4.** The suite maps that to NOT RUN. A7 and A8 stay NOT RUN for that reason, and S4 removes `Probe.NeedBuilt`.
10. **The glass client offers no CCS and an empty session id, and tolerates a CCS from the peer.** OpenSSL and Go accept this. The glass server echoes the client's session id and sends no CCS.
11. **`EncryptedExtensions` has no `group unchanged` check.** Design section 2.6 lists one. The group check runs at ServerHello, against the one group the client offered, so a second check at `ee` would always pass and show the learner nothing.

## S4, TLS 1.1

1. **A rule reads earlier facts from the transcript, and the session holds no second copy.** `Tls11Session.ClientRandom`, `ServerRandom`, and the server key parse the absorbed messages again. So the rules need no `Store` effect. TLS 1.3 keeps its facts through `Effect.Store`. Both shapes work. A new engine picks the one that fits how often the fact is read.
2. **One Probe session loop serves each TLS version through `ITlsEngine`.** The design had the session loop typed to one engine. `GlassTlsChannel` uses the same interface. SSH needs its own loop, because channels and exec have no match in TLS.
3. **`LabPair` names the server's check first.** In `L7-modern-server` both sides fail: the server names its refusal, and the client names alert 70. The lesson is the client's view, so `Lesson07Tls11` reports the client's code when alert 70 arrived. `TLS11_ALERT` is on the "peer only" list in `LabPair.Named`, as `TLS13_ALERT_RECEIVED` is, so `L7-downgrade` reports the TLS 1.3 client's sentinel check.
4. **A premaster's first two bytes must repeat the offered version.** RFC 4346 section 7.4.7.1 asks for this, and a failed check goes on with a random premaster, so the failure shows only at Finished.
5. **`Pkcs1` had no block with an empty DigestInfo prefix.** TLS 1.1 signs 36 bytes of MD5 then SHA-1 with no prefix. `SignMd5Sha1` and `VerifyMd5Sha1` share `EncodeDigestBlock` with the SHA-1 and SHA-256 forms.
6. **A key from the wire gets a shape check before any arithmetic.** `Tls11RsaKeys.TryReadPublic` refuses an even modulus, a modulus under 59 bytes, and an even exponent or one below 3, as `TLS11_SERVER_KEY_UNUSABLE`. Without it `BigUInt` throws an unnamed `ArgumentException` on an even modulus and `Pkcs1` throws `RSA_MESSAGE_TOO_LONG`.
7. **In Git Bash, `-p:NetCFRefDir=E:\dev\tools\netcf35-ref` loses its backslashes.** The build then says the CF references are missing. Use forward slashes or leave the flag out, because `Directory.Build.props` holds that default.

## S6

1. **Name known skips in the PR body.** A clean PR body said "a change to any token character is refused" while a test skipped the last character. The skip was the defect showing. A skip goes in the body, with its reason.
2. **A signature shows who calls only when the verifier already holds the key.** The first lab checked a signature against the key the caller sent, so any key earned a token. The issuer now holds an enrolment row, and it compares the answer to the challenge it sent.
3. **`Convert.FromBase64String` accepts set spare bits and whitespace on both builds.** To hold one spelling, encode the result and compare it to the text.
4. **`DateTime` subtraction ignores `Kind`.** A verifier that takes a `DateTime` must convert a local value and refuse one with no zone, or a local clock moves every expiry.

5. **The contract named the wrong alert for a removed client certificate.** RFC 8446 sections 4.4.2.4 and 6.2 name `certificate_required` for an empty list and `bad_certificate` for a corrupt certificate. Go sends alert 116 in a live run. Read the RFC before you wire an alert name from a design doc.
## S7

1. **Timing cases taken one after the other measure the machine, and they do not measure the compare.** This machine has 24 logical CPUs. A whole-case sample of the constant-time compare moved its mean between about 12 and 19 ticks from run to run. Sequential constant-time |t| ran from 3.7 to 230, and a control with two identical cases reached 89. So `TimingLab.Interleaved` takes turns of 100 samples between its two cases, and the lab uses it. `TimingLab.Sample` stays sequential because the contract names it.
2. **One run under |t| 4.5 is not a promise on this machine, even for identical cases.** Over 20 interleaved runs of 100,000 samples per case, the constant-time compare went over 4.5 in 5 of 20 runs (median 1.97, max 9.07). The identical-case control went over 4.5 in 1 of 20 (median 1.49, max 6.32). A second pass with ABBA turns gave 6 of 20 and 3 of 20. The largest mean difference was 0.18 ticks, against about 11 ticks for the leaky compare. So the lab prints `controlT` beside `constantTimeT`, and its check uses the 3 x rule only. Do not write "constant-time |t| stays under 4.5" in a tour.
3. **The lab's guess loop stretches each secret byte to a 1,024-byte block.** One loop pass takes about 0.33 ns, and the clock tick is 100 ns. Each round tries every candidate, so drift lands on all of them. At 10 rounds the lab missed a byte in 2 of 5 control runs. At 50 rounds it recovered the secret in 30 of 30 attack-row runs.
4. **A timing event has no wire bytes, so it carries its numbers as JSON text in `Plain`.** `TraceEvent` has no general payload field. The schemas are in `Native/TimingReport.cs`.
5. **A control run must have no failed check (A11.catalog).** So the constant-time guess reports its result with no check in a control run, and it fails the `constant-time compare` check only on the attack row. Each attack row holds one `LabOption` and no plan, because a row may change one field.
6. **`TimingVerdict` is `{LeakyT, ConstantT, Threshold, Separated}`, and `TimingJudge.Judge` takes four cases, per the contract on main.** The contract changed while this slice was open, so the first shape `{T, Separates}` went away. `TimingJudge.PairT` gives the t of one pair, for the control and the managed compare.
7. **`build.cmd` prints `'vswhere.exe' is not recognized` under vcvars when `vswhere` is off PATH.** The build still passes. Ignore the line.
8. **`LabTests` joined the non-parallel `timing` collection,** because `AttackCatalog.All` will hold timing rows at release, and a sibling test's load would change a measurement.
9. **Lesson 11 stays `built: false` until its tour and UI land, so no learner reaches it without the accuracy text (lead's ruling after Jared's review).** `LabCatalog.Find(11)` returns null, and `AttackCatalog.All` holds no lesson 11 row. `built` stays one decision with one control. The release steps are in `docs/lesson-11-names.md`.
10. **A failed guess proves only that the loop failed.** The check text names the samples per candidate, and the guess event names the stretch and the same-process timer. Do not write "flat timing" as a result of the lab.
## S4, SSH

1. **A local command enters the interpreter on the start message type.** `SshRows.Local` has a row from `Open` on `InboundMessage.StartType`, so the interpreter emits no received event for a command, and `Interpreter.cs` stays unchanged. The rule reads the command from `SshSession.Pending`.
2. **SSH rules change fields of their own session.** The design says a rule runs no side effect. SSH holds too much state for one `Secret` effect per field, so a rule writes to `SshSession` and returns all else as effects. It touches nothing outside that object, and a test can still call a rule with no socket.
3. **`EngineDuel` dropped the server's `Start` output.** The echo server said nothing at start. An SSH server sends its version line first. `EngineDuel` now passes those bytes.
4. **`_at += Header(tag)` reads `_at` before the call.** `Header` moved `_at`, and the sum then lost that move. The RSA parser read the wrong offset. Take the call's value in its own statement when the call moves the same field.
5. **Windows `ssh.exe` can end with a TCP reset after its last packet.** The pump reported `LINK_LOST` beside a good run. `ResetEndsStreamLink` makes reset 10054 the end of the stream, and the engine then decides: a finished session closes cleanly, and an unfinished one names `PEER_CLOSED_EARLY`.
6. **A lab names its tunnel targets, so a same-seed rerun gives the same bytes.** A loopback port changes on each run and sits inside `ChannelOpenTunnel`. The lab asks for `echo.lab:7`, and `EchoTarget.Open` maps that name to the real port.
7. **`DhGroup14` returns 256 fixed bytes, and X25519 returns 32.** The hashes take K as an mpint in both suites, and e and f too in group 14. `ByteWriter.Mpint` strips zeros and guards the top bit. Tests pin both forms.
8. **Both builds of a clause group share one `--work` folder.** `ssh.exe` needs a key file locked to one reader, and the second build then cannot overwrite it. `TrainingPki` deletes an older copy first. The rogue key in `SshClauses.cs` had the same problem, and the acceptance author fixed it.
9. **For S5: a server tunnel opens through `TransportRequest.OpenTarget`.** It defaults to a socket. The gateway passes its own link there, and `AllowTunnel` decides the target first. The engine confirms a channel before the target connects, so a failed connect shows as a channel that closes at once.
10. **The server decides a tunnel, as RFC 4254 section 7.2 says.** PR #38 named the client as the actor of `tunnel allow list`, and the claim reader caught it. The server now owns that check, through `Effect.CheckFailed`, and it stays open and sends `ChannelOpenFailure`. The client owns `tunnel accepted`, which only reports the answer. A real client could keep the session. The lab ends it with `SSH_TUNNEL_REFUSED`, and `LabResult.FailedCheck` names the server's check, since that check decided.
11. **A flipped length byte that still looks sensible makes the reader wait for bytes that never come.** `LINK_DEADLINE` ends that wait on both gates, by the S3 rule that the clock restarts only while the gate holds an event. PR #38 passed 0 in step mode and reported this as open, because it branched before S3 landed. A length no packet may hold ends at once in `SSH_PACKET_LENGTH`.
12. **The client's referee is Go, and the server's referee is `ssh.exe`.** Each referee is another SSH implementation. The `sshpeer` client mode has no independent peer, so no claim here rests on it.
13. **A peer's EOF closes the whole tunnel target.** `IByteLink` has no half close, so bytes the target sends after that are lost. `ssh.exe -W` passes, because its reply came before its EOF. S5 needs a half close if the gateway must carry late replies.
14. **`dotnet build` can lock `NetSec.Core.NetCF` for a run started right after a build.** One gate run reported `A9.cf.same-suite-passes-on-net48-skips-pinned` as `CS2012 ... being used by another process`. The next run passed 4 of 4 with no change. It is a build-server race, not a product fault.
15. **No pin refuses by name (Jared's review, blocker).** PR #38 made no pin mean any key, on every connect, and it stored nothing. Now no `known_hosts` text ends in `SSH_HOST_KEY_UNKNOWN`. Only `TrustFirstUse` accepts it, and `GlassSshSession.LearnedKnownHostsLine` returns the line to store. **For S5: `GlassSshLink` must pass `KnownHosts`, from `SshKeyBlob.Of` on the training host key or from a stored line. With neither, the CE link fails by name.**
16. **A window grant follows a read, never an arrival (Jared's review, blocker).** `Consumed` grants window back. A relay counts a chunk as read when its target write ends, and it stops reading its target while `WindowFull` holds. One session then holds at most 48 MiB, by the numbers in `SshRows`, under the 64 MiB of `DeviceProfile.Ce`. That figure is arithmetic. It was not measured on the CF runtime.
17. **Strict KEX is cheap, so both suites offer it.** It took one name in `KexInit`, a sequence reset after `NewKeys`, and a refusal of `Ignore` during the exchange. Source read this session: `draft-miller-sshm-strict-kex`, sections 3.1 to 3.3. A peer with no marker gets the old rules, so an old device still connects. Add `chacha20-poly1305` or an `-etm` MAC only with strict KEX required.
18. **The sequence number stops by name at 2^32.** RFC 4253 section 6.4 lets it wrap. RFC 4344 section 3.1 says not to send 2^32 packets under one key, and this engine has no rekey. The check runs in the writer and the reader, so a command path needs the same failure guard as a feed.
19. **A test can pass for the wrong reason on a closed channel.** The first second-confirmation test ran the exec to its end, so the channel had gone and the failure came from that. A rule-breaking test must assert the state it attacks is still live.

## S5, the bridge

1. **The gateway opens hop 2 at the first byte.** `ssh.exe -L` opens a tunnel for any local connection, and the suite's port check is one. An eager open started a TLS handshake that the check then cut, and that named `PEER_CLOSED_EARLY` in a good run. `FirstWriteOpensLink` opens nothing for an empty tunnel.
2. **A hop server starts before it knows the trace id.** The PIN pad makes the id and the envelope carries it, so the gateway's SSH handshake and the server's TLS handshake come first. `LateTraceSink` holds those events and writes them under the id when the first frame crosses. A session that ends first writes them with no id, so a tamper at the handshake still shows its check.
3. **A hop reads the trace id without proof, so it only labels with it.** The bank refuses before the MAC passes under no trace id, and names the claimed id in the detail.
4. **The pad holds a loaded key.** `PinPadCore.InjectedInitialKey` stands for a key loader's work, and a test pins it to what the bank derives. The base key is in `NetSec.Core.dll` on every process, because `TrainingKeySource` derives it from public text. So the boundary is what each role's code reads, and no binary hides anything.
5. **Open a live `tap` log with `FileShare.ReadWrite`.** The tap still holds it open.
## Pump deadline test

1. **The side whose deadline fires reports `LINK_DEADLINE`. The side that then reads the close reports `PEER_CLOSED_EARLY`, and that is its true outcome.** A test that names one side's code must fix the order with two deadlines. `LabPair.Named` drops the second code, so a lab reports the real failure in either order.
