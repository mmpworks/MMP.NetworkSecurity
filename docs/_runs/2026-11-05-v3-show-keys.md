## What changed

1. Core `TraceRedaction`: `Fingerprint(bytes)` gives "fp:" and the first 8 bytes of SHA-256 as hex. `Hide(event)` gives a new event in which each secret holds `fingerprint`, `length` and `hidden: "toggle"` instead of bytes. The input event does not change, so a fork still runs on the real bytes. C# 3, and the CF build passes.
2. `TraceSecret` gains `Fingerprint`, `Length` and `Hidden`, written only on a hidden secret. A shown line is the same as before, so the golden traces hold.
3. `TraceKeyUse` puts `typeId`, `version` and `provider` at the top of a `key.in-use` event.
4. `LabSession.Write` makes two lines per event, shown and hidden, and stores both. The file and the broadcast take the line the toggle names at that moment. `/events` picks by the toggle at the request, so a flip changes an open session at once.
5. `PUT /api/security/show-keys` broadcasts `{ type: "security.show-keys", on }`.
6. The key log answers HTTP 409 `KEYS_HIDDEN` while OFF. An os session still answers `KEYLOG_NOT_KEPT`.
7. `session.save` while OFF returns a hidden copy (`<file>.hidden.ndjson`) when the file holds shown lines. The original stays.
8. `session.load` hides the bytes while OFF, and its `session.started` gains `fileHidesKeys` when the file was saved OFF.
9. `key.in-use` on `<sessionId>/keys`, one per type the lab reads: the learner's key when the set holds one, else the built-in key. A type with no long-term key gets the event with no secret. `key.public` moves onto the same stream object, so the two never share a stream number.
10. `SecurityTypes.BuiltInKeyOf` in Core replaces the Host's copy of the type-to-key map.
11. Jared's #129 wording item rides here too (PR #135): a `PartialChain` refusal names both causes.
