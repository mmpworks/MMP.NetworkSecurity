## What changed

1. `src/NetSec.Vault`: `IVault` over one SQLite file. Keys are wrapped by AES-256-GCM under `vault/master.key`, with `name#version` as the additional data. Every call that names a caller writes a hash-linked audit row before it returns. A failed audit write refuses the call with `VAULT_AUDIT_FAILED`.
2. The my-login keys (`token.issuer`, `device.enrolment`) live in the vault. Flow keys are exportable. A lab reads them by `Export` with the caller `host/lab-<n>`. The key route reads them with `host/key-route`. The other types stay key files until their slice.
3. The vault exercise: `exercise/signing` and `exercise/derive`, non-exportable, made at the first start. Routes `POST /api/security/vault/exercise/{sign,derive,export,audit-check}`, `GET /api/security/vault/keys`, `GET /api/security/vault/audit`.
4. `OpenSslTool` holds the OpenSSL locate-and-run code that `FlowParts` held, so the exercise judges with the same program.
5. `THIRD-PARTY-NOTICES.md` section 6: the six NuGet packages, each licence read from the cache.
